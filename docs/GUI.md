# GUI.ps1 Documentation

The `GUI.ps1` script drives the Windows Presentation Foundation (WPF) interface. It handles user input validation, terminal output formatting, concurrent deployment threads, and interactive health monitoring.

## Key UI Elements

### 1. Main Window
- **Top Button Bar**: Triggers major application states (Add Server, Run Setup, Health Monitor, Manage Services).
- **Server Container**: A scrollable `StackPanel` that dynamically holds configuration blocks generated by `Add-ServerBox`.
- **Terminal Output**: A `RichTextBox` for real-time deployment logging, complete with a Simple/Advanced detail toggle.

### 2. Add-ServerBox (Configuration Block)
Dynamically creates a new visual grouping containing:
- **Core Info**: IP Address, Username, Password.
- **Service Selection**: Dropdown populated automatically from the `configs/services/` directory.
- **Traefik Toggle**: Checkbox to enable or disable the reverse proxy dependency.
- **Connection Configs**: Checkboxes and input boxes to enable/disable SSH and WinRM, and override their default ports (22 and 5985).

### 3. Health Monitor Window (`Show-HealthMonitorWindow`)
An advanced overlay utilizing background runspaces to poll server metrics without freezing the UI.
- **Server Health**: Displays CPU, Memory, Disk, and Load Averages with dynamic color-coding (Green/Yellow/Red).
- **Container Health**: Lists all running and stopped containers. Features embedded **Start, Stop, and Restart buttons** tied directly to the `RMSetup.psm1` module.
- **Health Report**: Generates an exportable text summary of all nodes.

## Core Functions

### Data Collection & Validation
- `Get-AllServerConfigs`: Iterates through the UI elements and constructs strongly-typed `[PSCustomObject]` payloads representing each server. Uses the unary comma (`,`) to prevent PowerShell array unrolling.
- `Test-IPAddress`: Ensures standard IPv4 strings or valid hostname formats.
- `Test-ServerConfigs`: Validates mandatory fields, enforces port bounds (1-65535), and ensures at least one connection protocol is toggled on.

### Threaded Execution (`$serverDeploymentScript`)
When "Run Setup" is clicked, `GUI.ps1` spins up a `RunspacePool`. 
It passes the configuration data into background threads, caches the OS using `Get-TargetOS`, applies the custom port configurations via `Set-ConnectionConfig`, and pipes real-time `Write-Host` output back to the UI thread using a thread-safe `ConcurrentQueue`.
